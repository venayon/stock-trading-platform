## 2. REST contracts

All IDs are UUID strings generated by the trader. JSON numbers for price are accepted as BigDecimal, but responses
render price as a six-decimal string to preserve decimal representation for JavaScript clients. Dates use ISO
`yyyy-MM-dd`; timestamps use UTC instants.

### Create trade

`POST /api/trades`, required `Idempotency-Key` (1–128 printable ASCII characters), optional `X-Correlation-ID`
(validated UUID; generate if absent/invalid).

```json
{
  "tradeDate": "2026-10-24",
  "side": "BUY",
  "symbol": "AAPL",
  "quantity": 10,
  "price": "123.450000",
  "currency": "USD",
  "counterparty": null
}
```

Accept price as a decimal JSON string or number; reject exponent notation in strings and fractional precision greater
than six unless extra digits are only zeros. Normalize to scale six with `RoundingMode.UNNECESSARY`. Require price >0
and precision <=18 after scaling (maximum 999999999999.999999). Quantity must be integral and >0 within signed long
range. Require tradeDate, strict BUY/SELL, symbol normalized trim/uppercase with Locale.ROOT matching
`[A-Z0-9][A-Z0-9.-]{0,15}`, currency matching `[A-Z]{3}` and a configured allowlist defaulting to USD/GBP/EUR. Omitted
currency defaults to USD; explicit null is invalid. Counterparty is optional, trimmed, <=128 characters; blank becomes
null. Date is a valid LocalDate within Avro int epoch-day range; do not impose calendar/market rules. Reject unknown
request fields to expose client mistakes.

Fresh success: HTTP 202 after acknowledged MongoDB insertion, `Location: /api/trades/{tradeId}`, echoed correlation
header. Response includes tradeId, publicationStatus PENDING, canonical trade fields and createdAt. It does not wait for
Kafka.

The relay later stores PUBLISHED and `event: {topic, partition, offset}` after Kafka ACK. Poll GET to observe this
transition. Same key + same canonical request returns 200 with the original ID/timestamp and current state, plus
`Idempotent-Replay: true`; it does not requeue published work. Same key + different canonical request returns 409.
Worker leases are internal and do not cause HTTP conflicts for valid same-payload retries. Broker/Registry errors leave
durable PENDING work; only storage failure/uncertainty returns 503 at acceptance. A client timeout is ambiguous: retry
with the same key.

Missing/invalid key, malformed JSON and validation failures return 400; absent resources 404; infrastructure unavailable
503; unexpected defects 500. ProblemDetail includes `type`, `title`, `status`, `detail`, `instance`, `correlationId`,
stable `errorCode`, optional field errors/trade ID/status. Never expose stack traces or connection strings.

### Query trades

- `GET /api/trades/{id}` returns 200 with canonical fields, publication status, timestamps and optional event metadata;
  404 if absent, 400 for malformed ID.
- `GET /api/trades?page=0&size=20&symbol=AAPL&side=BUY&publicationStatus=PUBLISHED` returns
  `{items,page,size,totalElements,totalPages}`. Max size 100, reject negative paging and unknown enum filters. Fixed
  sort `createdAt DESC, tradeId DESC`. No unbounded collection reads.

Pagination is a demo convenience: concurrent inserts can shift pages; it is not a snapshot/export contract.

### Processor endpoints

- `GET /api/processed/{id}` returns canonical trade, `processingStatus` (PENDING/COMPLETE), original source coordinates,
  routed output coordinates if complete, routeVersion and timestamps. 404 if absent.
- `GET /api/processed?page=0&size=20&symbol=AAPL&side=BUY&processingStatus=COMPLETE` uses the same paging envelope and
  bounds.
- `POST /api/process` with `{ "tradeId": "..." }` reads the immutable canonical trader document through a read-only
  Mongo source adapter. This is an explicit local-demo coupling: no direct updates to trader data. Unknown ID →404;
  source not PUBLISHED →409; already COMPLETE →200/no enqueue. Otherwise republish the source event to `stock-trades`
  with the original trade ID and symbol key, header `replay=true`, then return 202 with `replayPublication` metadata.
  This signals enqueue acknowledgment, not processing completion. Poll the processed GET endpoint. Source read/send
  failures →503. Repeated replay calls may enqueue duplicates but cannot create another logical processed trade. Replay
  cannot recover malformed bytes without a corrected canonical source document; DLT inspection and correction remain
  manual review work.

## 3. MongoDB documents and indexes

Use one MongoDB 7 server with separate logical databases `trader` and `processor`, separate collections. Standalone
Mongo is sufficient because each atomic operation affects one document; no multi-document transaction is assumed. Index
creation is an explicit bootstrap action, with uniqueness verified before accepting writes.

`trader.trades`:

| Field                                                          | Meaning                                                                  |
|----------------------------------------------------------------|--------------------------------------------------------------------------|
| `_id`                                                          | tradeId; unique primary key                                              |
| `idempotencyKey`, `requestHash`                                | unique key; SHA-256 of versioned canonical payload                       |
| canonical trade fields                                         | date as ISO string, quantity as Int64, price as Decimal128, enum strings |
| `publicationStatus`                                            | PENDING or PUBLISHED                                                     |
| `event`                                                        | topic, partition, offset; absent before acknowledgment persisted         |
| `publicationAttempts`, `lastPublicationError`, `nextAttemptAt` | persisted relay retry metadata                                           |
| `leaseToken`, `leaseUntil`                                     | conditional-update fencing token                                         |
| `createdAt`, `updatedAt`, `correlationId`                      | audit/recovery context                                                   |

Indexes: unique `idempotencyKey`; `(publicationStatus,nextAttemptAt,leaseUntil)`; `(createdAt DESC,_id DESC)`;
`(symbol,createdAt DESC,_id DESC)`. Do not TTL-delete idempotency keys independently of trades. No retention/deletion
API in this scope.

Hash input: fixed field order, UTF-8 canonical JSON, canonical strings, date ISO, long quantity, six-decimal price,
explicit null counterparty, prefix `trade-request-v1`. Exclude generated IDs, correlation headers and timestamps.
Duplicate-key races load the winning document and compare hashes; they do not become 500 errors.

`processor.processed_trades`: `_id=tradeId`, `inputHash`, canonical fields, first-seen source topic/partition/offset,
status, routeVersion=1, target partition, output coordinates, timestamps, attempts and lease fields. Unique `_id`; query
indexes mirror trader. Same ID/different payload is a terminal identity conflict routed to DLT, never an overwrite. Read
input from Kafka as authoritative; Mongo source access is only for manual replay.

## 4. Producer state machine and failure behavior

```text
new request --atomic insert + Mongo ACK--> PENDING --HTTP 202
                                             |
relay: due/expired lease --claim token--> Avro send --Kafka ACK--> PUBLISHED
                                             |
                                         failure
                                             |
                                PENDING with bounded backoff
```

1. Validate key and canonicalize before insertion. Insert-first under a unique binary key index; duplicate-key races
   read the stored record and compare the versioned payload digest. Acceptance and pending intent are one document.
2. Relay claims one due PENDING document atomically, setting a fresh token, a 60-second lease and incrementing
   publicationAttempts. Missing lease/retry fields in older records remain eligible.
3. Map LocalDate/BigDecimal to generated Avro types; send keyed by symbol with tradeId, X-Correlation-ID and
   schemaVersion headers. Verify the source topic has six partitions. Registry schema must already be registered.
4. Configure acks=all, producer idempotence, max in-flight 5, delivery timeout 10s, request/metadata blocking timeouts
   3s and Registry connect/read timeouts 3s with retries disabled. Await the send future for up to 11s after send
   returns; serialization/metadata acquisition occurs before that wait. These ordinary bounds fit inside the lease;
   process pauses can still outlive it.
5. After ACK, conditionally set PUBLISHED and coordinates only while the token still owns the PENDING document. Stale
   completions are ignored. On failure, conditionally retain PENDING with sanitized PUBLICATION_FAILED and
   nextAttemptAt; if Mongo itself is unavailable, lease expiry permits recovery.
6. Poll every second, process at most 20 records serially per poll, and back off failed records from 2s to 60s. No
   producer DLT, terminal drop or retry limit exists. Inspect pending age, attempt/error fields and logs until
   monitoring is implemented.

Leases fence Mongo updates, not sends from paused old owners. Kafka producer idempotence handles transport retries
within a session, not application retries/restarts. Crash after ACK and before completion can duplicate physical events.
Stored coordinates identify one acknowledged send, not all sends. Consumers must deduplicate trade IDs.

| Failure window                               | Durable outcome / response                                    |
|----------------------------------------------|---------------------------------------------------------------|
| Mongo insert fails or ACK is lost            | HTTP 503; outcome may be ambiguous, retry the same key        |
| Crash after insert/HTTP response             | PENDING; relay/restart discovers durable intent               |
| Kafka/Registry unavailable or send times out | Acceptance remains 202; relay keeps PENDING and retries       |
| Kafka ACK then Mongo completion fails        | Remains PENDING or ambiguously completed; retry may duplicate |
| Completion persisted then process restarts   | PUBLISHED; no further claim/send for that trade               |

## 5. Consumer processing, routing and recovery

Listener deserializes String keys and specific StockTrade values through ErrorHandlingDeserializer. Validate symbol/key
match, trade fields and immutable ID before persistence. A malformed payload is never silently coerced.

Processing order: acquire/upsert PENDING → compute/persist route → publish output and wait for ACK → mark COMPLETE with
output coordinates → return → container commits offset. Disable asynchronous/out-of-order acknowledgments. A COMPLETE
duplicate increments dedup count and returns without sending. A live PENDING lease raises a retryable error; do not
return successfully and commit its offset prematurely. During long operations keep total bounded handling/retry time
below `max.poll.interval.ms=300000`; start with `max.poll.records=10` and monitor rebalances.

Route version 1, exactly six target partitions:

```java
int bucket = Math.floorMod(symbol.hashCode(), 3); // canonical ASCII symbol
int partition = (side == BUY ? 0 : 3) + bucket;
// ProducerRecord(topic, partition, symbol, stockTrade)
```

Use Java String.hashCode deliberately; document equivalent behavior for other languages. Examples: AAPL hash 2001436 →
BUY 1 / SELL 4; MSFT hash 2375924 → BUY 2 / SELL 5. Route is side+symbol, so one symbol's BUY and SELL events may be
processed independently. Persist routeVersion and partition; startup rejects a target topic partition count other than
six. Source uses Kafka's String-key partitioning, not this output algorithm. Do not compare source and target partition
numbers as if they were the same policy.

Output retains the StockTrade value and symbol key; headers add source topic/partition/offset, routeVersion and
processor correlation ID. Missing/invalid input correlation IDs receive a generated UUID; record that the original
header was invalid without logging arbitrary content. Preserve original valid correlation ID end to end; each HTTP
replay gets its own operation correlation ID.

DefaultErrorHandler: initial attempt + three retries at 1s. Nonretryable deserialization, validation and identity
conflicts go directly to recovery. For recovery, DeadLetterPublishingRecoverer sends to `stock-trades-dlt` using the
source partition; enable verification of send result and throw on publication failure. Configure recovered-record
handling/offset commits explicitly for RECORD ack mode, and prove the policy using committed-offset tests. A recovery
exception must never be swallowed. Outages of Mongo/Kafka may eventually DLT a valid event; replay after repair is the
operational response. This deliberately favors visible isolation over infinite blocking.

DLT record preserves original bytes for deserialization failures and original Avro value for decoded failures. Configure
DelegatingByTypeSerializer with byte[]→ByteArraySerializer and StockTrade→KafkaAvroSerializer; use
ErrorHandlingDeserializer for keys too and support raw key bytes in DLT serialization. Preserve original
topic/partition/offset/key, exception class, sanitized reason, correlation ID and delivery attempt headers. Trim stack
traces/duplicate retry headers to bound record size. Registry is needed to inspect Avro-valued DLT entries; malformed
raw bytes remain undecodable by definition.

Fault tests must show: no source offset advance when both processing and DLT fail; acknowledged DLT permits progress;
duplicate output after ACK/crash is possible; COMPLETE dedup prevents a second logical Mongo result. Retrying later
records or replaying DLT events does not restore strict chronological order.

## 6. Logs, metrics and runtime configuration

JSON logs: timestamp UTC, level, service, environment, logger, message/eventName, correlationId, tradeId,
topic/partition/offset where applicable, attempt, durationMs, outcome, errorCode, exceptionClass. Do not log full
bodies, secrets or counterparty values. Copy MDC into publisher/reconciler tasks and clear it in finally blocks.
Correlation IDs belong in headers/logs, never metric labels.

Micrometer meters map to the names frozen in HLD section 9. Counter definitions: accepted increments only on successful
fresh document creation; published counts acknowledged sends; processed counts first persisted COMPLETE transition;
deduplicated counts COMPLETE repeats; errors have bounded `stage` and `code` labels; DLT counts acknowledged recovery
sends. Timers measure publication and each listener attempt with outcome tags. Gauges count pending source documents,
committed lag per partition and lag sampling health. Gauges may lag data by one poll; counter increments can be lost on
a crash, so reconcile business counts from Mongo, not Prometheus.

Actuator exposes health/info/prometheus on the service port, private local deployment only. Readiness checks required
Mongo and messaging dependencies; liveness does not fail merely because Kafka is unavailable. Prometheus stays available
during dependency outages. Graceful shutdown stops new requests/polls and drains bounded in-flight operations before
exiting. Reconciler leases expire safely after forced shutdown.

Use Boot's dependency management for Spring/Kafka APIs; declare deliberate Avro/serializer overrides, inspect conflicts
and enforce no duplicate generated classes. Add no API authentication, real order execution or financial calculations in
these iterations.

## 7. Acceptance invariants

1. Invalid input produces no Mongo document and no Kafka event.
2. One idempotency key identifies one canonical immutable request and trade ID.
3. Every 202 from trader has durable PENDING intent. Event metadata appears only after Kafka ACK and completion
   persistence; idempotent retries reuse the ID and observe current status.
4. Durable PENDING state remains visible and recoverable after restart.
5. Each valid consumed trade has at most one logical processed document; physical Kafka duplicates are permitted.
6. No committed source offset skips a record without completed processing or acknowledged DLT recovery.
7. Every output partition matches route version 1 and malformed bytes reach DLT without listener death.
8. No metric uses tradeId, correlationId, symbol or exception messages as labels.
